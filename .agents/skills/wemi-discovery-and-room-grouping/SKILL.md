## 1. Core Responsibilities & Domain Ownership

The **Antigravity Device Discovery & Room Grouping Agent** owns the internal logic connecting raw LAN UPnP/SSDP responses to organized, human-meaningful rooms, Room v6 SQLite (`MIGRATION_5_6`), Home Screen widgets, and on-device hardware rules inspection/safety:

1. **Multi-Stage SSDP, Unicast & ChromeOS ARCVM Discovery Orchestration ([`DiscoveryCoordinator.kt`](../../../app/src/main/java/org/suppressingfire/wemi/data/DiscoveryCoordinator.kt), [`HomeProfileSanitizer.kt`](../../../app/src/main/java/org/suppressingfire/wemi/data/HomeProfileSanitizer.kt), [`ProvisioningCoordinator.kt`](../../../app/src/main/java/org/suppressingfire/wemi/data/ProvisioningCoordinator.kt), [`DeviceCrudAndRulesCoordinator.kt`](../../../app/src/main/java/org/suppressingfire/wemi/data/DeviceCrudAndRulesCoordinator.kt), [`SsdpDiscoveryEngine.kt`](../../../app/src/main/java/org/suppressingfire/wemi/network/SsdpDiscoveryEngine.kt), [`LanSubnetHintResolver.kt`](../../../app/src/main/java/org/suppressingfire/wemi/network/LanSubnetHintResolver.kt), [`NetworkMonitor.kt`](../../../app/src/main/java/org/suppressingfire/wemi/network/NetworkMonitor.kt), [`DeviceDescriptorFetcher.kt`](../../../app/src/main/java/org/suppressingfire/wemi/network/DeviceDescriptorFetcher.kt), [`DeviceActionsUiController.kt`](../../../app/src/main/java/org/suppressingfire/wemi/ui/DeviceActionsUiController.kt))**:
   - Coordinates network-bound UDP multicast `M-SEARCH` (`239.255.255.250:1900` via `MulticastSocket(null)` + `activeNetwork.bindSocket` + `networkInterface` + `MulticastLock`, excluding VPNs and ChromeOS `arc0` by name/IP while keeping Phone `10.22.22.x` Setup AP top priority), aligned post-burst retransmit timing (`550ms`/`1.25s` on Phones & TVs; `100ms` settle + `700ms`/`2.0s` on ARCVM), `ensureActive()` cancellation, `ssdp:byebye` & `ST`/`NT` non-Belkin guard, non-Belkin `LOCATION` RFC 1918 host IP harvesting, `selectSearchTargetAndScan` / `scanManualSubnet` superseded-job cancellation, deterministic loopback UDP test mirroring (`registerLoopbackSsdpPort`), order-preserving `Semaphore(3)` concurrent Stage A/B descriptor probing via `LanRuntimeUtils.expectedHardwareIdentity`, placeholder-serial- & CGNAT-safe Stage B known-device 9-port unicast verification across `/setup.xml` and `/Lightsetup.xml` (unescaping XML entities in `<friendlyName>` & `<MetaInfo>` via `XmlAndSkuParser.unescapeXml`), manual-IP 9-port hardware enrichment + `<serialNumber>`/`<UDN>` deduplication (`saveDevice`), trimmed home- & room-scoped `moveDeviceOrder(..., withinRoomOnly)`, and RFC 1918-only Stage C `/24` subnet unicast sweeps (`shouldRunUnicastSubnetFallback` + `LanSubnetHintResolver` 5-tier physical `/24` resolver + `Semaphore(24)` across `49153, 49152, 49154, 49151` via Wi-Fi-bound `wifiSocketFactory`).
   - Serializes device adoption via `adoptMutex` (`HomeProfileSanitizer.kt`, prioritizing exact serial/UDN/endpoint matches before name-only candidates in `adoptDiscoveredDevices` while preserving verified Tier-2 hardware rules capabilities whenever `firmwareVersion` is unchanged), isolates per-device `Mutex` locks via `DeviceEntity.concurrencyKey()`, registers immediate `<100ms` Real-LAN GENA push subscriptions with 3-tier `NOTIFY` routing (skipping unroutable RFC 6598 CGNAT callbacks on ChromeOS ARCVM with `15s` foreground SOAP polling), and bounds all SOAP probes with the shared `Semaphore(3)` so 2nd-Gen RTOS switches never drop TCP connections.
2. **Deterministic 3-Tier / Symmetric 4-Pass Hardware Identity Resolution (`DeviceEntity.matchesDiscovered`, `SsdpDiscoveredDevice.matchesEndpointOrSerial`, `findMatchingExistingDevice`, `findMatchingDiscoveredDevice` & `WidgetRemoteViewsBuilder.resolveTargetDevice`)**:
   - **Tier 1 / Pass 1 (`<serialNumber>` via `!LanRuntimeUtils.isPlaceholderSerial`)**: Real non-placeholder serials match **if and only if** equal (case-insensitive).
   - **Tier 2 / Pass 2 (`<UDN>` / `USN` via `LanRuntimeUtils.canonicalHardwareUdn`)**: Strips `::urn:...`, rejects placeholder-derived UDNs, and requires exact UDN equality whenever both sides have canonical UDNs.
   - **Tier 3 / Passes 3a & 3b (Exact Endpoint → Non-Loopback Same-IP Port-Hop → `<friendlyName>` Fallback + Cross-Device Claim Protection)**: Used only when at least one side lacks a real serial and canonical UDN; keeps `127.0.0.1` loopback servers isolated by port and prevents offline blank-serial switches from hijacking peer hardware.
3. **Automatic Room Inference, Word-Bounded Category/Holiday Classification, Canonical Grouping & Non-Destructive Legacy Room Migration ([`DeviceEntities.kt`](../../../app/src/main/java/org/suppressingfire/wemi/data/DeviceEntities.kt) & [`RoomAndCategoryRules.kt`](../../../app/src/main/java/org/suppressingfire/wemi/data/RoomAndCategoryRules.kt))**:
   - **`normalizeDeviceNameForInference(deviceName)`**: Splits acronym-to-CamelCase and lower-to-upper CamelCase boundaries and normalizes `_`, `-`, `/`, `.` to spaces before word-bounded matching across `inferRoomFromName`, `classifyDeviceCategory`, and `isHolidayLightDevice`.
   - **`inferRoomFromName(deviceName)`**: Specificity-ordered `ROOM_INFERENCE_RULES` (`"Kitchen"`, `"Dining Room"`, `"Ensuite"` before `"Bedroom"`, `"Hallway & Landing"`, `"Bedroom"`, `"Outdoor"`, `"Garage"`, `"Basement"`, `"Office"`, `"Living Room"`, low-priority `"upstairs"`/`"downstairs"` floor fallback, `"Unassigned"` fallback).
   - **`normalizeRoomName`, `groupDevicesByCanonicalRoom` & `resolveDeviceRoomAssignment`**: Merges case-variants, sorts `"Unassigned"` last across Phone/Tablet/TV/Widgets, preserves custom user rooms and Demo Showroom rooms, and migrates blank / `"Unassigned"` / legacy `"Living Room"` switches automatically.
4. **Zero-Permission Subnet Home Sync, ChromeOS CGNAT Hygiene & Soft-AP SSID Shielding (`HomeProfileSanitizer.kt`, `ProvisioningCoordinator.kt`, `DeviceCrudAndRulesCoordinator.kt`, `XmlAndSkuParser.kt`)**:
   - Filters out Belkin soft-AP SSIDs (`WeMo.*`, `Wemo.LS3W.*`), preserves known router SSIDs, blocks phantom RFC 6598 CGNAT (`100.64.0.0/10`) homes, backfills physical `subnetPrefix`, and repairs polluted multi-home rows on startup.
5. **On-Device Hardware Rules Capability Detection, Read-Only `rules.db` Extraction & Anti-Brick Safety Engine ([`HardwareRulesModels.kt`](../../../app/src/main/java/org/suppressingfire/wemi/network/HardwareRulesModels.kt), [`HardwareRulesClient.kt`](../../../app/src/main/java/org/suppressingfire/wemi/network/HardwareRulesClient.kt), [`HardwareRulesProtocol.kt`](../../../app/src/main/java/org/suppressingfire/wemi/network/HardwareRulesProtocol.kt), [`HardwareRulesDbCodec.kt`](../../../app/src/main/java/org/suppressingfire/wemi/network/HardwareRulesDbCodec.kt), [`HardwareRulesSafetyValidator.kt`](../../../app/src/main/java/org/suppressingfire/wemi/network/HardwareRulesSafetyValidator.kt), [`HardwareRulesCoordinator.kt`](../../../app/src/main/java/org/suppressingfire/wemi/data/HardwareRulesCoordinator.kt), [`HardwareRulesSection.kt`](../../../app/src/main/java/org/suppressingfire/wemi/ui/components/HardwareRulesSection.kt))**:
   - **Zero-RTT Tier-1 Detection (`/setup.xml`)**: `XmlAndSkuParser.inferRulesCapabilityFromSetupXml` adds zero extra LAN requests during SSDP/unicast scans. Recognizes that late OpenWrt builds (`PVT-OWRT-SNS`) may emit `<rtos>1</rtos>` (never misclassifying `OWRT` as RTOS) while RTOS devices (`-RTOS-`, `Dimmer-2_0`, `OutdoorPlug`, `WDS060`, `WSP080`, `WSP090`) still list `urn:Belkin:service:rules:1` in `/setup.xml` despite lacking `FetchRules`.
   - **Authoritative Tier-2 Verification & Firmware Caching**: `HardwareRulesClient.probeRulesCapability` inspects `GET /rulesservice.xml` first to fast-reject RTOS devices lacking `FetchRules`/`StoreRules`, then confirms via `POST /upnp/control/rules1#FetchRules` (`VERIFIED_SUPPORTED` vs `VERIFIED_UNSUPPORTED`). Offline/unreachable switches never get falsely downgraded. Verdicts persist in Room v6 (`SwitchDatabase.MIGRATION_5_6`) keyed by `firmwareVersion`, letting `HardwareRulesCoordinator` skip re-probing verified RTOS devices unless `forceRecheck = true`.
   - **Anti-Brick Safety & Read-Only Extraction**: Downloads binary ZIPs via `LanHttpClient.getBytes` (`<= 2 MiB`), rejects ZIP path traversal (`..`, `/`, `\`), verifies 16-byte SQLite 3 magic and `PRAGMA integrity_check`, queries `sqlite_master` / `PRAGMA table_info(RULEDEVICES)` for schema tolerance across firmware versions, rotates up to 5 untouched raw-ZIP backups per switch, checks `timesync1#GetDeviceTime` clock drift, and gates all `StoreRules` writes behind `HardwareRulesSafetyValidator` (`<= 512 KiB` SQLite / `<= 128 KiB` ZIP, rejects `"`, `;`, `--`, CR/LF, NUL against unparameterized firmware C `snprintf` SQL, enforces `DayID` in `1..7` or `-1` exclusively for `Long Press`, `RuleDuration > 0` for `Time Interval`, `CountdownTime > 0` for `Countdown Rule`, requires `<errorInfo>` `"Successful"`, and enforces post-store `FetchRules` read-back version verification).

## 2. Seven Non-Negotiable Discovery, Room Grouping, On-Device Rules & Release Invariants

1. **Unrecognized or Blank Names/Rooms Must Default to `UNASSIGNED_ROOM` (`"Unassigned"`), Never `"Living Room"`**.
2. **Evaluate Specific Functional Rooms (`"Ensuite"`) Before Broad & Floor Modifiers (`"Bedroom"`, `"upstairs"`/`"downstairs"`)**.
3. **Short Ambiguous Tokens Must Use Pre-Compiled Word-Boundary Regexes (`RoomAndCategoryRules.kt`)**.
4. **Enforce 3-Tier / Symmetric 4-Pass Hardware Identity, RFC 6598 CGNAT Safety & `resolveDeviceRoomAssignment` Across All Discovery, Provisioning, Manual Save, GENA & Widget Flows**.
5. **Zero-RTT Discovery Overhead & Strict Anti-Brick Rules Safety**:
   - Never issue `/rulesservice.xml` or `FetchRules` inside bulk SSDP/unicast scans (`SsdpDiscoveryEngine` only reads Tier-1 hints from `/setup.xml`).
   - Never misclassify `PVT-OWRT-*` firmware as unsupported when `<rtos>1</rtos>` is present, never downgrade an offline switch to `VERIFIED_UNSUPPORTED`, and never allow `StoreRules` to send unvalidated SQLite bytes or bypass post-store `FetchRules` read-back verification.
   - Keep `SwitchDatabase.MIGRATION_5_6` non-destructive so existing user homes, switches, and rooms survive upgrades intact.
6. **Unit, Hardware Rules, ChromeOS, Governance, Widget & E2E Tests Must Pass (`100%` `< 500L` `.kt` Files, `0` Lint Errors, `100644` Script Modes)**:
   - Run `sh gradlew testDebugUnitTest --rerun-tasks lintDebug assembleDebug` covering all suites including `HardwareRulesTest`, `HardwareRulesE2ETest`, `DiscoveryAndGroupingIntegrationTest`, `ChromeOsArcVmDiscoveryTest`, `ChromeOsArcVmE2ETest`, and `LicenseAndBrandGovernanceTest`.
7. **Stage 2 Release Sign-Off Gate & Zero-Idle-Polling Stop Policy**:
   - During an active release cycle (`CURRENT_TURN: discovery_and_grouping`), complete the discovery/room-grouping/on-device-rules audit and advance cleanly to `telemetry_and_debugging` via `bash scripts/advance_release_turn.sh`. **Never** arm or re-arm `scripts/await_release_turn.sh` after `SIGNED_OFF` or when `CURRENT_TURN: NONE`.
